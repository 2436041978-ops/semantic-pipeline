绕过编辑器手写 YAML 会怎样

5 类典型格式错误及其后果

① 缺 immutable_boundaries

契约没有红线，等于没有约束力 → 入库校验 FIELD_INCOMPLETE 拦截

② version: "1.0" 非 SemVer

版本对账依赖三段式语义化版本 → 字段级校验直接拒绝

③ llm_constraints 挂错层级

约束挂在 visual_mapping 下，编译器找不到 → SCHEMA_VIOLATION

④ "文案要友好一点"不可判定

主观描述无法编译为机器规则 → description 必须含现象+根因+后果

⑤ 无现象+根因+后果

字段级校验要求 description 三要素齐全，缺一不可入库

≡

表单校验规则

字段级 + 令牌级两层规则

字段级

intent_id → [A-Z]{3}-\d{3}

如 ERR-001、ACT-001，正则实时校验

semantic_domain → 下拉自字典

只能选已注册的四个覆盖层

version → SemVer 三段式

v1.1.0 合法，"1.0" 拒绝

令牌级

description / visual_mapping / llm_constraints 必填

缺任一字段无法提交

tokens 全部下拉自令牌表

color_token、motion_token、icon_token 不可手输

五项前置校验（含拦截实例）

非法契约能被拦住吗？——逐项验证

① 覆盖层存在性

SEMANTIC_DOMAIN_UNDEFINED

写入 semantic_domain: custom_domain → 字典无此覆盖层，拦截

② 绑定存在性

BINDING_UNDEFINED

引用 status.unknown → 令牌表无此绑定，拦截

③ 场景一致性

SCENARIO_DOMAIN_MISMATCH

transactional 场景引用 observational 专属令牌 → 跨层引用，拦截

④ 字段完整性

FIELD_INCOMPLETE

缺 immutable_boundaries + version "1.0" 非 SemVer → 拦截

⑤ 结构合法性

SCHEMA_VIOLATION

YAML 缩进错误 / 字段挂错层级 → Schema 校验不通过，拦截

{ }

错误响应格式

每次拦截返回可定位的结构化错误

{
  "code": "BINDING_UNDEFINED",
  "message": "引用的语义绑定 status.unknown 在令牌表中不存在",
  "location": "semantic_tokens.error_severity.fatal.visual_mapping.color_token",
  "severity": "error",
  "action": "reject"
}

code 定责 · location 定位 · action 决定 reject / warn

消费方对账逻辑

✓ 版本一致 + checksum 匹配 → 正常加载

⚠ 版本过期 → CONTRACT_VERSION_MISMATCH

触发 warning，通知重新编译

✗ checksum 不匹配 → ARTIFACT_TAMPERED

reject_load，产物被拒绝加载
