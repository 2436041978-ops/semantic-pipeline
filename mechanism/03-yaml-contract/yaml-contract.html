YAML 契约 YAML Contract

YAML 契约不是"自由写规则"，而是"查字典写约定书"——先查语义域（场景），再查语义令牌（级别），最后生成契约实例。
每个值都有字典出处，非法引用在编译前置校验时直接阻断。

1

每个值都有字典出处

semantic_domain 和 semantic_tokens 的值全部来自语义字典，非法引用被编译前置校验阻断

2

查字典流程可被复现

不同设计师对同一组件查字典，得到相同的语义域和语义令牌，消除主观差异

3

契约是代码资产而非文档

具备机器可读、自动校验、版本管理、多格式分发四项能力

A

场景 A：删除账户按钮

用户说："我要一个删除账户的界面。"——查字典写约定书完整流程

1

查语义域（场景）

打开《② 语义域》，找到 transactional（交易/操作页，会改数据）

semantic_domain: transactional ← 查字典得出
2

查语义绑定

在 transactional 域下，找到 destructive_action（不可逆操作）

semantic_binding: destructive_action ← 查字典得出
3

查语义令牌表

打开《① 语义令牌表》，查到具体的语义级别、视觉映射、LLM 约束

status.critical
action.destructive
组件：Alert + Button + Modal
4

写约定书（YAML 契约）

把查到的值填进 7 字段，每个值都有字典出处

intent_id: "ACT-001"
description: "AI 把不可逆操作做成普通按钮，没有二次确认"
version: "1.0.0"
semantic_domain: "transactional"              # ← 查《② 语义域》
applicable_products: ["*"]
semantic_tokens:
  destructive_action:
    description: "不可逆的数据销毁操作"
    visual_mapping:
      color_token: "status.critical"           # ← 查《① 语义令牌表》
      button_style: "outline_danger"           # ← 查《① 语义令牌表》
    llm_constraints:
      - "必须包含二次确认弹窗"
      - "文案必须明确说明'此操作不可恢复'"
      - "必须提供取消选项，且视觉权重不低于确认按钮"
immutable_boundaries:
  - boundary_type: "safety"
    rule: "禁止直接执行删除操作而不显示二次确认"
    violation_action: "block"

✓ 结论：这份 YAML 里的每一个值，都不是编的，而是从《① 语义令牌表》和《② 语义域》里查出来的。

B

场景 B：错误状态分级

用户说："我们产品的错误提示用户总投诉看不懂。"——查字典写约定书完整流程

1

查语义域（场景）

打开《② 语义域》，找到 observational（观察/通知页，用户需要理解系统状态）

semantic_domain: observational ← 查字典得出
2

查语义绑定

在 observational 域下，找到 error_state（错误状态）

semantic_binding: error_state ← 查字典得出
3

查语义令牌表

打开《① 语义令牌表》，查到 error_severity 有四个级别

fatal
红色脉冲
transient
灰色加载
retryable
黄色提示
degraded
蓝色提示
4

写约定书（YAML 契约）

把查到的值填进 7 字段，每个值都有字典出处

intent_id: "ERR-001"
description: "多种错误共用红色，用户无法判断后果严重程度"
version: "1.1.0"
semantic_domain: "observational"              # ← 查《② 语义域》
applicable_products: ["*"]
semantic_tokens:
  error_severity:
    fatal:
      description: "系统级故障，对话上下文可能丢失"
      visual_mapping:
        color_token: "status.critical"         # ← 查《① 语义令牌表》
        motion_token: "pulse.red.urgent"       # ← 查《① 语义令牌表》
        icon_token: "alert.octagon"            # ← 查《① 语义令牌表》
      user_action:
        - label: "刷新页面"
          action: "refresh"
        - label: "导出历史"
          action: "export_history"
    transient:
      description: "网络抖动，系统可自动恢复"
      visual_mapping:
        color_token: "status.neutral"          # ← 查《① 语义令牌表》
        motion_token: "spinner"
        icon_token: "loader"
      user_action:
        - label: "等待自动恢复"
          action: "wait"
    retryable:
      description: "请求频率已达上限"
      visual_mapping:
        color_token: "status.warning"          # ← 查《① 语义令牌表》
        motion_token: "none"
        icon_token: "clock"
      user_action:
        - label: "等待倒计时"
          action: "wait_countdown"
    degraded:
      description: "部分功能可用，可继续生成"
      visual_mapping:
        color_token: "status.info"             # ← 查《① 语义令牌表》
        motion_token: "none"
        icon_token: "info.circle"
      user_action:
        - label: "继续生成"
          action: "continue"
immutable_boundaries:
  - boundary_type: "safety"
    rule: "禁止所有错误状态共用同一种红色视觉表达"
    violation_action: "block"

✓ 结论：不管是"删除账户"还是"错误状态"，流程完全一样——先查语义域定场景，再查语义令牌表定级别，最后把查到的值写成 YAML 约定书。

7

7 字段定义（v1.0 冻结，只增不减）

每个字段的值都是从字典里查出来的，不是自由编的

# 字段 类型 必填 说明 值从哪来
1 intent_id string 是 关联漂移模式 ID，命名 {领域缩写}-{三位序号} 查 6 个漂移模式 匹配结果
2 description string 是 现象 + 根因 + 后果，一句话说清 查 组件语义快照 的 6 字段记录
3 version string 是 SemVer x.y.z：主版本 = 破坏性变更，次版本 = 功能新增，修订号 = 文案修复 契约库 版本管理规范
4 semantic_domain enum 是 引用字典已注册覆盖层，引用而非自创 查《② 语义域》
5 applicable_products string[] 是 生效产品；["*"] 全局，可配 excluded_products 排除 查产品清单
6 semantic_tokens map 是 核心：语义级别 × 视觉映射 × 用户行动 × LLM 约束 查《① 语义令牌表》
7 immutable_boundaries object[] 是 红线：{boundary_type, rule, violation_action} 查语义域的约束规则 + 令牌表的禁止型约束

⚠️ 关键理解：字段 4（semantic_domain）和字段 6（semantic_tokens）的值不是编的，是查字典查出来的。如果填了一个字典里没有的值（比如 semantic_domain: "shopping_cart"），编译前置校验会直接阻断，提示"未注册的语义域，请先查字典"。

✕

非法引用阻断演示

先注册、后引用——契约引用字典写成的场景语义规则文件

✓ 合法引用

intent_id: "ERR-001"
semantic_domain: "observational"       # ← 字典已注册
semantic_tokens:
  error_severity:
    fatal:
      visual_mapping:
        color_token: "status.critical"  # ← 字典已注册
编译通过 ✓

✕ 非法引用 — 被阻断

intent_id: "ERR-001"
semantic_domain: "shopping_cart"       # ← 字典未注册 ❌
semantic_tokens:
  error_severity:
    fatal:
      visual_mapping:
        color_token: "status.danger"    # ← 字典未注册 ❌

[CI 阻断] dictionary-reference-not-found

semantic_domain: "shopping_cart" 未在语义字典注册。

color_token: "status.danger" 未在语义令牌表注册。

请先走字典变更流程：快照证据 → 诊断归档 → 候选模式 → 评审入典

Prompt 前缀
在生成致命错误界面时：
- 必须使用红色脉冲视觉
- 必须包含八边形警告图标
- 必须提供恢复路径按钮
- 文案必须说明后果严重性
- 禁止在 observational 域使用
JSON Schema
{
  "intent_id": "ERR-001",
  "semantic_domain": "observational",
  "semantic_tokens": {
    "error_severity": {
      "fatal": {
        "color_token": "status.critical",
        "motion_token": "pulse.red.urgent",
        "icon_token": "alert.octagon"
      }
    }
  }
}
