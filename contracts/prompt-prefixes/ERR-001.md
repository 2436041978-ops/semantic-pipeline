> 适用范围：observational 域下的错误状态展示

## 绝对不能碰的红线

1. **禁止把多种错误状态做成同一种红色视觉表达**
2. **禁止仅显示"出错了""Something went wrong"等无后果说明的文案**
3. **禁止 fatal 级别错误不提供用户恢复路径**
4. **禁止同一产品内不同错误级别共用同一文案模板**

---

## 颜色背后的意思（语义令牌）

- **fatal** → `status.critical`（红色脉冲 + 八边形图标）→ 用户行动：刷新页面 / 导出历史 / 联系客服
- **transient** → `status.neutral`（灰色加载 + 旋转图标）→ 用户行动：等待自动恢复 / 手动重试
- **retryable** → `status.warning`（黄色静态 + 时钟图标）→ 用户行动：等待倒计时 / 升级套餐
- **degraded** → `status.info`（蓝色静态 + 信息图标）→ 用户行动：继续生成 / 简化问题重试

---

## LLM 强制约束

- 必须明确告知用户"对话上下文可能已丢失"（fatal）
- 必须提供恢复路径（刷新/导出/联系客服）
- 禁止使用"出错了"等模糊文案
- transient 文案必须包含"正在恢复"或"请稍候"
- retryable 必须显示倒计时或预计恢复时间
- degraded 必须说明哪些功能受影响、哪些可用
