快照模板 · 2.1 模板生成

空白模板能保证结构完整吗？ Template Generation

快照是整条证据链的源头。如果快照字段缺失、标注不含语义，后续的模式匹配、契约生成都会建立在错误的地基上。
空白模板通过强制 6 字段结构，从源头守住质量。

1

6 字段强制结构

空白模板预设 6 个必填字段，任何字段缺失时提交按钮禁用

2

字段类型约束

每个字段有明确的类型和取值范围，自由文本被限制在特定槽位内

3

机器可消费

结构化快照可直接被模式匹配引擎消费，无需二次解析自然语言

≠

对比：自由文本记录 vs 6 字段结构化模板

同样的界面偏差，两种记录方式的质量差异

✕ 自由文本 不可机器消费

"用户反馈说报错页面的红色太刺眼了，而且文案写得让人很慌，不知道该怎么办。建议改得温和一点，或者加个重试按钮。"

❌ 组件类型不明：是 Alert？Modal？Toast？
❌ 视觉特征缺失：红色是哪种红？脉冲还是静态？
❌ 文案未记录：原文案是什么？
❌ 交互未记录：是否有重试按钮？当前有没有？
❌ 场景未记录：什么错误？什么上下文？
❌ 偏差未量化："太刺眼"无法被机器解析
✓ 6 字段模板 可直接消费 
{
  "component_type": "Alert",
  "visual": {
    "color": "red",
    "background": "solid",
    "icon": "warning"
  },
  "copy": {
    "title": "Error",
    "description": "Something went wrong",
    "tone": "urgent"
  },
  "interaction": {
    "dismissible": true,
    "actions": ["retry"]
  },
  "context": "system_error",
  "deviation": {
    "type": "severity_undifferentiated",
    "severity": "retryable",
    "current_visual": "red_solid",
    "expected_visual": "yellow_static"
  }
}
✓ 组件类型：Alert（明确）
✓ 视觉特征：红色实心 + 警告图标（可匹配）
✓ 文案内容：标题 + 描述 + 语气（可比对）
✓ 交互特征：可关闭 + 重试操作（可校验）
✓ 使用场景：系统错误（可分类）
✓ 偏差描述：类型 + 级别 + 当前/预期（可量化）
6

6 字段空白模板

每个字段必填、类型约束、缺失时提交阻断

1
component_type string · enum
组件类型：Alert / Button / Modal / Progress / Toast / Stepper
必填
2
visual object
视觉特征：color_token / background / icon_token / motion_token
必填
3
copy object
文案内容：title / description / tone / language
必填
4
interaction object
交互特征：dismissible / actions / disabled / loading
必填
5
context string · enum
使用场景：system_error / user_action / notification / onboarding
必填
6
deviation object
偏差描述：type / severity / current_value / expected_value / evidence_screenshot
必填

字段缺失阻断演示

{
  "component_type": "Alert",

  "copy": { "title": "Error" },
  "interaction": { "dismissible": true },
  "context": "system_error"
  // ❌ deviation 字段缺失
}

验证结论

空白模板通过强制 6 字段结构，确保每条快照在提交时即具备完整的语义描述能力。
字段缺失时提交按钮禁用，从源头杜绝了"半条记录入库"的风险。
这证明了：空白模板能保证结构完整。
