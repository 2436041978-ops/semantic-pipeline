消费点注册：声明消费什么契约

每个消费点接入时必须注册

consumers:
  - consumer_id: "prompt-err-gen"
    type: "prompt_prefix"
    consumes: [{ contract: "ERR-001", format: "prompt_prefix" }]
  - consumer_id: "ci-stylelint"
    type: "ci_rule"
    consumes: [{ contract: "ERR-001", format: "ci_rule" },
               { contract: "ACT-001", format: "ci_rule" }]
  - consumer_id: "comp-alert-val"
    type: "component_validator"
    consumes: [{ contract: "ERR-001", format: "json_schema" }]
  - consumer_id: "designops-check"
    type: "checklist"
    consumes: [{ contract: "ERR-001", format: "checklist" }]
consumer_id 消费点唯一标识
type 消费格式类型（prompt / ci / checklist / schema）
consumes 声明消费的契约 ID 和格式
registered_at 注册时间戳，追踪接入时效

2.2

对账与告警

消费滞后与断点，能不能在"没人发现约束缺席"之前被抓住？不是等 DesignOps 人工排查，而是机器自动对账：版本滞后告警、零消费告警、超时断点告警。

⚙

对账引擎检测逻辑

reconciliation.yaml · 三类告警阈值与动作

rules:
  version_lag:            # 版本滞后
    check_interval: "5m"
    threshold: { warning: "1d", critical: "7d" }
    action:
      warning:  "notify_consumer_owner"
      critical: "block_pr + notify_team_lead"

  zero_consumption:       # 零消费
    check_interval: "1d"
    threshold: { warning: "7d", critical: "30d" }
    action:
      warning:  "notify_consumer_owner"
      critical: "archive_consumer + notify_designops"

  pipeline_timeout:       # 超时断点
    check_interval: "1m"
    threshold: { ci_trigger: "5m", prompt_inject: "10m" }
    action:
      timeout: "alert_pipeline_owner + auto_rollback_check"

超时断点告警

正常链路 vs 断点链路对照

✓ 正常链路（对照）

契约提交T+0s
编译管线触发T+30s
4 种格式编译完成T+2min
分发至消费点T+3min
消费点加载并上报T+5min

✗ 断点链路（告警）

契约提交 / 编译 / 分发T+0s → T+3min ✓
消费点加载并上报T+15min · 超时

[ALERT] pipeline-timeout

消费点 designops-check 在编译完成后 12 分钟仍未上报加载记录

可能断点：分发失败 / 消费点未重启 / 加载逻辑异常

2.3

拦截统计与收益归因

消费追踪的终点不是"用了"，而是"用了之后拦住了什么、值多少"。按模式 ID / 消费格式 / 契约版本归因，按返工成本模型推演收益。

1

拦截归因：每次拦截记录完整上下文

模式 ID / 消费格式 / 契约版本 / 消费点

# interception_log.yaml
interception_id: "INT-20260712-001"

# 归因维度
pattern_id: "ERR-001"        # sub: retryable
contract_version: "v1.1.0"
consumer_format: "prompt_prefix"
consumer_id: "prompt-err-gen"

# 拦截内容
detected_issue: "同义词降级"
  input: "请求过于频繁，请稍后再试"
  expected_token: "status.warning"
  ai_output_color: "red"
  violation: "retryable 错误使用了 status.critical 视觉"

# 拦截动作
action: "override + notify"
  override_result: "将视觉修正为黄色 + 时钟图标"

# 成本归因
rewind_cost_model: "ERR-001-retryable"
  estimated_savings: "2.5h"
pattern_id 被触发的漂移模式（ERR-001 / ACT-001 等）
contract_version 拦截时生效的契约版本
consumer_format 拦截由哪种消费格式触发
consumer_id 具体消费点，定位责任边界
rewind_cost 按模式定义的单次返工成本
