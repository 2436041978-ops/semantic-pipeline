# 语义翻译设计师：从视觉生产者到语义规则定义者

> **写给谁看**：体验架构设计师、交互设计师、设计系统设计师——正在从"画图"转向"定规矩"的人。
> **你能得到什么**：一套"采集语义快照 → 诊断漂移模式 → 编写 YAML 契约 → 维护语义字典"的完整工作流，让你在 AI 生成界面时代拥有不可替代的语义定义能力。

---

## 一、角色定位（待续）

从"视觉生产者"到"语义规则的定义者与翻译者"。

**核心职责预览**：
- 6 字段语义快照采集
- 三层判定模型执行（组件类型 → 语义缺失 → 视觉校验）
- 模式卡片归档与版本管理
- 语义字典条目注册与维护
- YAML 契约编写与版本声明

---

## 二、三个痛点（待续）

1. 漂移案例分散无法归档
2. 诊断标准因人而异
3. 契约写成后无人消费

---

## 三、产出资产（待续）

- 语义快照（6 字段结构化记录）
- 模式卡片（症状 + 根因 + 证据 + 关联契约）
- YAML 契约（7 字段机器可读规则）
- 语义字典条目（覆盖层 / 绑定 / 场景映射）

## 五、能力模型（预览）

**不需要**：
- 写 React / Vue / CSS
- 调 AI 模型参数
- 搭建设计系统

**必须会**：
- 观察界面，发现"意思跑偏了"
- 写 YAML 规则文件（缩进 + 冒号）
- 理解语义令牌、覆盖层、不可变边界的定义方式
- 做 A/B 对比验证

## 六、协作关系（待续）

**上游输入**：设计师/PM 反馈的新场景、用户投诉/工单
**下游输出**：DesignOps 运营契约库、前端消费编译产物、管理层查看验证报告

---

## 七、快速开始（今天就能做）

1. 阅读《组件语义快照：我观察 AI 产品界面时用的 6 字段记录法》
2. 打开模式库，浏览 6 个已验证模式卡片
3. 选择一个你熟悉的产品，按 6 字段格式记录 1 张语义快照
4. 尝试匹配到已知模式，或归档为新候选模式
