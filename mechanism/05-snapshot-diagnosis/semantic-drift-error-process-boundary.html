⑥ 语义漂移的三类典型断裂：从错误状态、过程状态到边界动作

三类典型断裂验证 Three Typical Breaks

验证三个孤立事故是否共享同一个根因结构。ERR-001 / PRO-001 / BND-001 不是三篇独立事故报告，
而是同一个系统性缺陷在三种组件类型上的三次全链路复现。

1

三个"感觉不对"，是三个孤立事故吗？

来自不同产品、不同场景的真实用户反馈

颜色

"AI 是在查出来的还是猜出来的？我不知道该不该信这个结果。"

表面问题

进度

BND-001 边界动作

"对话历史还在吗？还能继续聊吗？为什么突然结束了？"

表面问题

文案

核心命题

表面看是三个不相干的问题——颜色不对、进度模糊、文案混乱。但沿三层判定模型走完一遍，归档结果呈现惊人一致的骨架：
布尔值/裸字符串压缩了语义维度 → AI 按视觉惯性生成 → 用户按猜测行动。
三个案例，同一骨架。骨架的一致性本身就是"系统性缺陷"的直接证据。

2

三类断裂各自的证据链

每个模式的完整链路：缺失令牌 → 压缩信号 → 被压掉的维度 → 用户错误行动

缺失令牌

error_severity

语义令牌未在字典中注册，导致 AI/前端无法获取分级信息

压缩后的接口信号

isError: true  # 布尔值，丢失了"有多严重"

被压掉的语义维度

有多严重（fatal / transient / retryable / degraded）

用户的错误行动

刷新丢失内容

用户把限流（retryable）误判为系统崩溃（fatal），执行了错误的恢复动作

跨产品证据

ChatGPT 文心一言 通义千问

3

三案并排：同一骨架的三次显形

三个模式共用同一根因结构

维度 ERR-001 PRO-001 BND-001
组件类型 错误状态 过程状态 边界动作
缺失令牌 error_severity process_phase boundary_action
压缩后的接口信号 isError: true status: "searching" blocked: true
被压掉的语义维度 有多严重 在干什么、可信度多少 权利还在不在
用户的错误行动 刷新丢失内容 盲信或弃用结果 白费力气或放弃会话
Before 共性 视觉走查合规，语义错误
After 共性 令牌入典 + 契约注入 + 机器校验

同一骨架结论

三个案例，同一骨架——布尔值/裸字符串压缩了语义维度 → AI 按视觉惯性生成 → 用户按猜测行动。

这不是三个 bug，是一个系统性缺陷的三次显形。补令牌、立契约、机器校验，一次投入，全品类生效。

5

一句话总结

五个角色对三类典型断裂的认知

D

设计师

"红色用错、进度模糊、拒绝混同，都不是你画得不好——是组件库里没有语义级别的挂载点。"

三个模式共享同一个根因：设计稿（②）到组件库的语义压缩。修复不是让设计师"画得更规范"，而是在组件库中挂载语义令牌映射（error_severity / process_phase / boundary_action）。
