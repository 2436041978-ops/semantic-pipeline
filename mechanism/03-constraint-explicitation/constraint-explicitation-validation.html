隐含假设暴露

当前 AI 工具的隐含假设是："所有错误状态都应该用红色表达"。
这个假设从未被写成规则，但深深嵌在 Prompt 和组件库中。结果是：限流（retryable）和系统崩溃（fatal）长得一模一样，用户不知道是该刷新还是该等待。

三层诊断判定

Layer 1 · 组件类型

错误提示（Alert / Message）

Layer 2 · 语义缺失

后果差异未分级 · 恢复路径不明确

Layer 3 · 视觉校验

颜色映射不匹配 · 所有错误共用红色

2

生成显式规则

Contract Library · 把隐含假设写成机器可读的 YAML 契约

已编译

约束显化前（隐含）

# 没有规则文件
# 设计师心里知道："严重错误用红色"
# 前端心里知道："Alert 组件默认红色"
# LLM Prompt 里写："错误提示用红色背景"

# 结果：所有错误都是红色
# 用户无法区分 fatal / transient / retryable

约束显化后（显式）

intent_id: "ERR-001"
semantic_domain: "observational"

semantic_tokens:
  error_severity:
    fatal:
      description: "系统级故障，对话上下文可能丢失"
      visual_mapping:
        color_token: "status.critical"
        motion_token: "pulse.red.urgent"
        icon_token: "alert.octagon"
    transient:
      description: "网络抖动，系统可自动恢复"
      visual_mapping:
        color_token: "status.neutral"
        motion_token: "spinner"
        icon_token: "loader"
    retryable:
      description: "请求频率已达上限"
      visual_mapping:
        color_token: "status.warning"
        motion_token: "none"
        icon_token: "clock"
    degraded:
      description: "部分功能可用，可继续生成"
      visual_mapping:
        color_token: "status.info"
        motion_token: "none"
        icon_token: "info.circle"

immutable_boundaries:
  - boundary_type: "safety"
    rule: "禁止所有错误状态共用同一种红色视觉表达"
    violation_action: "block"

约束显化的核心动作

把原本散落在设计师脑子、产品文档、前端组件默认值里的隐含语义假设，
提取成一份机器可读的 YAML 契约：

• semantic_tokens：定义了 4 个 error_severity 级别，每个级别有明确的 color_token、motion_token、icon_token
• immutable_boundaries：用 safety 边界强制禁止"所有错误都用红色"这一隐含假设继续生效

约束显化闭环证明

1. 隐含假设被发现：Semantic Pipeline 诊断出"所有错误都用红色"是一个未声明的假设。
2. 显式规则被编写：Contract Library 生成 ERR-001.yaml，定义了 4 个 severity 级别和 2 条不可变边界。
3. 规则被验证有效：Validation Toolkit 语义分级器证明，同一文案在约束显化前后输出完全不同的视觉表达。
4. 规则被系统消费：Observability Layer 显示 3 个消费者正在引用该契约，tokens 消费率 100%，boundaries 执行率 100%。

约束显化完成：隐含的语义假设已变成显式规则，并且被证明有效、被系统消费。
