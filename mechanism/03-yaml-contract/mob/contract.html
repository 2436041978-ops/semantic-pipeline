1

契约真身

ERR-001.yaml · 设计意图的机器可读接口

intent_id: "ERR-001"
semantic_domain: "observational"
semantic_tokens:
  error_severity:
    fatal:      # 系统级故障，对话上下文可能丢失
      visual_mapping:
        color_token:  "status.critical"
        motion_token: "pulse.red.urgent"
        icon_token:   "alert.octagon"
      user_action: [刷新页面, 导出历史]
    transient:  # 网络抖动，系统可自动恢复
      visual_mapping:
        color_token:  "status.neutral"
        motion_token: "spinner"
        icon_token:   "loader"
      user_action: [等待自动恢复, 手动重试]
    retryable:  # 请求频率已达上限
      visual_mapping:
        color_token:  "status.warning"
        motion_token: "none"
        icon_token:   "clock"
      user_action: [等待倒计时, 升级套餐]
    degraded:   # 部分功能可用，可继续生成
      visual_mapping:
        color_token:  "status.info"
        motion_token: "none"
        icon_token:   "info.circle"
      user_action: [继续生成, 简化问题重试]
immutable_boundaries:
  - boundary_type: "safety"
    rule: "禁止所有错误状态共用同一种红色视觉表达"
    violation_action: "block"
  - boundary_type: "clarity"
    rule: "每个错误级别必须提供明确的用户行动指引"
    violation_action: "warn"

💡 关键理解

这不是"规范文档的代码版"，而是设计意图的接口定义。semantic_tokens 定义了"什么意思"，immutable_boundaries 定义了"不能做什么"。

四种机器形态

同一份契约，如何被不同机器消费

🤖 Prompt 前缀 给 AI 编程工具 
【语义约束前缀 · ERR-001】
1. FATAL（系统级故障）：
   颜色 status.critical（红色脉冲）· 图标 alert.octagon
   必须提供恢复路径（刷新/导出）
2. TRANSIENT（网络抖动）：
   颜色 status.neutral（灰）· 图标 loader · 禁止红色背景
3. RETRYABLE（限流）：
   颜色 status.warning（黄）· 图标 clock
   必须显示倒计时或升级入口
4. DEGRADED（部分可用）：
   颜色 status.info（蓝）· 图标 info.circle
   必须说明可用功能
【不可变边界】
- 禁止：所有错误状态共用同一种红色视觉表达
- 违反动作：BLOCK（直接拦截）

消费场景 · Cursor / Copilot / v0：Prompt 前缀在 AI 生成界面之前注入上下文。AI 不再按概率猜测颜色，而是按契约约束生成——约束从"需要被想起"变成"已经在场"。

注入方式：system prompt 前缀 / .cursorrules / 项目级 AI 指令

📐 JSON Schema 给结构校验器 
{
 "$id": "err-001.schema.json",
 "properties": {
   "error_severity": {
     "enum": ["fatal","transient","retryable","degraded"]
   },
   "visual_mapping": {
     "properties": {
       "color_token": { "enum": [
         "status.critical","status.neutral",
         "status.warning","status.info" ] },
       "motion_token": { "type": "string" },
       "icon_token":   { "type": "string" }
     },
     "required": ["color_token","icon_token"]
   }
 },
 "allOf": [{ "if": {
   "properties": { "error_severity": { "const": "retryable" } }
 }, "then": {
   "properties": { "visual_mapping": { "properties": {
     "color_token": { "not": { "const": "status.critical" } }
   } } }
 } }]
}

消费场景 · TypeScript / Zod / AJV：编码时实时校验。开发者传入非法 color_token 组合时，编辑器直接标红，类型系统拒绝编译通过。

校验时机：编码时实时 / 构建时静态分析

📋 Checklist 给设计师走查

□ 是否区分了 Fatal/Transient/Retryable/Degraded 四级？

□ 每级是否有不同的颜色（红/灰/黄/蓝）？

□ 每级是否有明确的用户行动指引？

□ Fatal 是否有恢复路径（刷新/导出）？

□ Retryable 是否有倒计时或升级入口？

□ 是否禁止了所有错误共用同一种红色？

□ 是否引用了意图契约 ERR-001？

【严重级别速查表】

级别颜色图标用户行动
fatal红脉冲alert.octagon刷新 / 导出
transient灰loader等待 / 重试
retryable黄clock倒计时 / 升级
degraded蓝info.circle继续 / 简化

消费场景 · 设计评审 / QA 验收：Checklist 不是"规范文档的精简版"，而是"契约真身的消费视图"。每条都对应 YAML 中的一个语义令牌或不可变边界。

走查时机：设计评审 / 交付验收 / 回归测试

⚙️ CI 规则 给自动化流水线 
# 编译自：contract/err-001.yaml
rules:
  error-severity-color:
    description: "禁止所有错误状态共用同一种红色"
    selector: "[data-severity]"
    mapping:
      fatal:     { color: "#cf1322", bg: "rgba(207,19,34,0.15)" }
      transient: { color: "#a0a0a0", bg: "#1e1e22" }
      retryable: { color: "#f5a623", bg: "rgba(212,136,6,0.15)" }
      degraded:  { color: "#4a9eff", bg: "rgba(22,119,255,0.15)" }
    forbidden:
      - selector: "[data-severity='retryable']"
        forbidden_color: "#cf1322"
        action: "block"
        message: "限流提示禁止使用红色（status.critical）"
      - selector: "[data-severity='transient']"
        forbidden_color: "#cf1322"
        action: "block"
        message: "网络错误禁止使用红色"
  error-action-completeness:
    description: "每个错误级别必须提供用户行动"
    required_children: ["[data-action]"]
    action: "warn"
    message: "错误状态缺少用户行动按钮"

消费场景 · GitHub Actions / GitLab CI：代码合并前自动执行。不合规的提交被阻断，无法进入主分支——约束从"人记得检查"变成"机器强制执行"。

执行时机：PR 创建时 / 合并前 / 定时回归

机器拦截现场

AI 试图生成违规内容时，四种形态如何接力拦截

🤖 AI 生成请求

AI 选择级别：retryable（限流）
AI 选择颜色：红色（status.critical）❌ 违规 vs 黄色（status.warning）✓ 合规
