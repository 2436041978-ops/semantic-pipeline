2.1

模板生成

空白模板能保证结构完整吗？

对比

自由文本 vs 6 字段模板

同一条反馈，两种记录方式

自由文本

"Alert 是红色的，实心的，看着挺吓人"
// 哪个组件？哪种红？用户该怎么办？——都没有

6 字段模板

{ component_type: "Alert",
  visual: "red solid banner",
  copy: "Something went wrong",
  interaction: "dismiss only",
  context: "system_error",
  deviation: "技术错误码直接暴露" }
结构

6 字段模板规范

枚举约束 + 缺失阻断 · 左右滑动

字段类型约束/枚举必填
component_typeenumAlert / Button / Modal / Progress / Toast / Stepper必填
visualstring颜色 + 形态 + 动效必填
copystring界面原文，禁止转述必填
interactionstring用户可执行的动作必填
contextenumsystem_error / user_action / notification / onboarding必填
deviationstring与语义预期的偏差描述必填

字段缺失阻断演示

deviation 字段未填 → snapshot-field-missing · 提交按钮置灰禁用，无法绕过

2.2

智能预填与降级

语义智能体填的草稿可信吗？

场景 A

高置信度 · 预填成功

清晰描述 → 综合置信度 94% ≥ 85% 通过

输入：清晰截图 + "限流提示用红色 Banner，只有关闭按钮"

component_type: "Alert"          # 置信度 99%
visual: "red solid banner"       # 96%
copy: "Too many requests (429)"  # 97%
interaction: "dismiss only"      # 91%
context: "system_error"          # 88%
deviation: "限流未与致命错误分级"  # 92%
—— 综合 94% ≥ 85% → 草稿预填通过

✓ 6 字段全部自动填入，人工只需过目确认

场景 B

低置信度 · 强制降级

模糊描述 → 综合 31% → 宁可空白，不可失真

输入：模糊截图 + "这个弹窗感觉不太对"

component_type: "Modal?"   # 置信度 45%  ⚠
visual: "???"              # 20%  ✗
copy: ""                   # 无法提取  ✗
interaction: "?"           # 15%  ✗
context: "unknown"         # 28%  ✗
deviation: "感觉不对"       # 不可结构化 ✗
—— 综合 31% < 40% → 强制清空，返回空白模板

降级处理：6 字段全部标红，要求人工逐项确认填写

阈值

三档置信度处理规则

≥85%

预填通过，草稿直接进入人工过目

≥60%

单字段警告标黄，提示人工重点核对该字段

<40%

强制清空，返回空白模板 —— 宁可空白，不可失真

2.3

提交校验

失真的快照能入库吗？

规则链

三层提交校验规则

字段完整性 / 语义一致性 / 字典引用合法性

① 字段完整性

失败率 0.3%

6 字段缺一不可，缺失即阻断

② 语义一致性

失败率 2.1%

字段之间不能自相矛盾（见场景 A）

③ 字典引用合法性

失败率 0.8%

枚举值必须在语义字典注册范围内

场景
