同一次漂移，两种记录方式

ERR-001：错误状态后果差异未分级

BEFORE · 散点案例的三种形态

形态 A：截图文件夹

ChatGPT_错误状态_红色混乱.png
文心一言_连接断开_红色.png
Kimi_429_红色.png …

❌ 文件名即全部信息，没有根因、没有修复路径

形态 B：Excel 表格

产品 │ 组件 │ 问题描述 │ 优先级 — "四种错误共用红色 │ P1"

❌ 只有现象，没有根因+后果，检索不出来

形态 C：语雀文档片段

"ChatGPT 的四种错误状态共用同一种红色……建议错误状态分级显示。"

❌ 对人可读，对机器不可查；没有 pattern_id，没有与令牌表绑定

AFTER · 模式卡片 
pattern_id: "ERR-001"
component_type: "错误状态"
name: "后果差异未分级"
description: |
  症状：流式中断 / 网络故障 / 限流 / 服务异常四种错误同红
  根因：缺少 error_severity 语义令牌，前端只接收 isError = true
  后果：用户无法判断后果严重程度，不知道该刷新还是等待
preview: "patterns/ERR-001/preview.png"
evidence: ["ChatGPT", "文心一言", "通义千问", "Kimi", "DeepSeek"]
✓ pattern_id 精确指向，跨产品关联 ✓ 标准化枚举，机器可检索 ✓ 现象+根因+后果，机器可判定 ✓ 5 产品证据，覆盖度可统计
4

四层结构化归档

从散点记录到组织资产的四层跃迁

L1

标识与分类

pattern_id: ERR-001 ✓ 精确指向，跨产品关联 · component_type: 错误状态 ✓ 标准化枚举，机器可检索

L2

语义描述

name "后果差异未分级" ✓ 一句话说清断层本质 · description 症状+根因+后果 ✓ 机器可判定同一模式

L3

证据归档

preview 统一证据入口 · evidence 5 个产品（ChatGPT / 文心一言 / 通义千问 / Kimi / DeepSeek）✓ 覆盖度可统计

L4

契约绑定

模式卡片 ERR-001 → YAML 契约 intent: ERR-001 → 编译输出 Prompt / Schema / CI。✓ 诊断→契约→验证全链路可追溯

6 字段逐字段差异对照

每个字段解决了散点案例的什么痛点 · 左右滑动

字段Before（散点痛点）After（模式卡片）带来的能力
pattern_id文件名"红色混乱.png"，无唯一标识ERR-001 精确指向跨产品关联，直接引用
component_type"错误状态"还是"报错"？无标准分类"错误状态"标准化枚举机器可检索，经验可复用
name无命名，无法口头引用"后果差异未分级"团队共同语言
description"四种错误共用红色"只有现象症状+根因+后果结构化机器可判定同一根因
preview截图分散，新人找不到patterns/ERR-001/preview.png 统一路径卡片即证据索引
evidence无结构化产品列表5 产品列表，机器可追踪自动提醒待验证产品
