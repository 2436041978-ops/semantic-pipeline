契约消费追踪 · 2.3 拦截统计与收益归因

拦截统计与收益归因 Impact Attribution

消费追踪的终点不是"用了"，而是"用了之后拦住了什么、值多少"。
按模式 ID / 消费格式 / 契约版本归因，按返工成本模型推演收益。

1

拦截可被归因

每次拦截记录模式 ID、消费格式、契约版本、消费点，形成可追溯的归因链

2

返工成本可量化

按模式定义返工成本模型：设计返工 + 前端返工 + 测试返工 + 用户投诉处理

3

价值可被推演

拦截价值 = 拦截次数 × 单次返工成本，形成可量化的 ROI 证据

1

拦截归因：每次拦截记录完整上下文

Interception Attribution · 模式 ID / 消费格式 / 契约版本 / 消费点

拦截日志示例

# interception_log.yaml
interception_id: "INT-20260712-001"
timestamp: "2026-07-12T13:42:18Z"

# 归因维度
pattern_id: "ERR-001"
  sub_pattern: "retryable"
contract_version: "v1.1.0"
consumer_format: "prompt_prefix"
consumer_id: "prompt-err-gen"

# 拦截内容
detected_issue: "同义词降级"
  input: "请求过于频繁，请稍后再试"
  expected_token: "status.warning"
  ai_output_color: "red"
  violation: "retryable 错误使用了 status.critical 视觉"

# 拦截动作
action: "override + notify"
  override_result: "将视觉修正为黄色 + 时钟图标"
  notification_sent: true

# 成本归因
rewind_cost_model: "ERR-001-retryable"
  estimated_savings: "2.5h"

归因维度说明

pattern_id 被触发的漂移模式（ERR-001 / ACT-001 等）
contract_version 拦截时生效的契约版本
consumer_format 拦截由哪种消费格式触发（prompt / ci / checklist / schema）
consumer_id 具体消费点，用于定位责任边界
rewind_cost 按模式定义的单次返工成本
2

返工成本模型

Rewind Cost Model · 按模式定义拦截一次 = 避免多少返工

ERR-001 · 错误状态后果差异未分级

设计返工：1.5h（重新分级视觉）
前端返工：1.0h（调整颜色映射）
测试返工：0.5h（补充边界用例）
用户投诉处理：2.0h

单次返工成本：5.0h

ACT-001 · 高危操作风险未约束

设计返工：2.0h（重新设计确认流程）
前端返工：1.5h（实现二次确认）
测试返工：1.0h（安全测试）
用户投诉处理：3.0h

单次返工成本：7.5h

ALR-001 · 告警文案语义降级

设计返工：0.5h（文案修正）
前端返工：0.2h（无需代码变更）
测试返工：0.3h（文案校验）
用户投诉处理：1.0h

单次返工成本：2.0h

ROI 推演：契约投入 vs 拦截收益

Return on Investment · 可量化的价值证据

投入成本（月度）

契约编写与维护 40h
编译管线运维 20h
消费点接入 30h
对账与告警响应 10h
总投入 100h

拦截收益（月度）

避免设计返工 180h
避免前端返工 120h
避免测试返工 60h
避免用户投诉处理 126h
总收益 486h
ROI = 收益 / 投入 4.86x

每投入 1 小时维护契约体系，避免 4.86 小时的返工成本。这还未计入品牌声誉损失、用户流失等难以量化的收益。
