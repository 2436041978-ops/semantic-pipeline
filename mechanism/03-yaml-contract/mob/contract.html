# intent/err-001.yaml
intent_id: "ERR-001"
semantic_domain: "observational"
version: "v1.1.0"
semantic_tokens:
  error_severity:
    fatal:      # 系统级故障，对话上下文可能丢失
      visual_mapping:
        color_token:  "status.critical"
        motion_token: "pulse.red.urgent"
        icon_token:   "alert.octagon"
      user_action: [刷新页面, 导出历史]
    transient:  # 网络抖动，系统可自动恢复
      visual_mapping:
        color_token:  "status.neutral"
        motion_token: "spinner"
        icon_token:   "loader"
      user_action: [等待自动恢复]
    retryable:  # 请求频率已达上限
      visual_mapping:
        color_token:  "status.warning"
        motion_token: "none"
        icon_token:   "clock"
      user_action: [等待倒计时, 升级套餐]
    degraded:   # 部分功能可用，可继续生成
      visual_mapping:
        color_token:  "status.info"
        motion_token: "none"
        icon_token:   "info.circle"
      user_action: [继续生成]
immutable_boundaries:
  - boundary_type: "safety"
    rule: "禁止所有错误状态共用同一种红色视觉表达"
    violation_action: "block"
  - boundary_type: "clarity"
    rule: "每个错误级别必须提供明确的用户行动指引"
    violation_action: "warn"

# 版本: v1.1.0 | 生成时间: 2026-07-12T13:40:00Z
[SEMANTIC_CONSTRAINTS_START]
1. FATAL（系统级故障）：
   红色脉冲 + 八边形警告图标
   必须提供恢复路径（刷新/导出）
   禁止仅显示"出错了"等模糊文案
2. TRANSIENT（网络抖动）：
   灰色加载 + 旋转图标 · 禁止红色背景
   必须说明"系统正在自动恢复"
3. RETRYABLE（限流）：
   黄色提示 + 时钟图标
   必须显示倒计时 · 必须提供升级入口
4. DEGRADED（部分可用）：
   蓝色提示 + 信息图标
   必须说明可用功能 · 提供"继续生成"选项
不可变边界（强制执行）：
- 禁止所有错误状态共用同一种红色视觉表达
- 每个错误级别必须提供明确的用户行动指引
[SEMANTIC_CONSTRAINTS_END]

🔧 形态 4 · CI 规则 GitHub Actions / ESLint 自动拦截

# .github/workflows/semantic-check.yml
# 由编译管线从 ERR-001.yaml 自动生成
name: Semantic Contract Check
on: [pull_request]
steps:
  - name: Load Semantic Contract
    run: sp-load intent/err-001.yaml
  - name: Check Error Severity Colors
    run: |
      sp-check --rule "error_severity_color" \
        --forbid "status.critical" for "retryable" \
        --forbid "status.critical" for "transient" \
        --forbid "status.critical" for "degraded"
    failure(): |
      echo "❌ 语义违规：错误状态颜色映射不符合契约"
      echo "修正建议："
      echo " - retryable → status.warning（黄色）"
      echo " - transient → status.neutral（灰色）"
      echo " - degraded  → status.info（蓝色）"
      exit 1
  - name: Check User Actions
    run: |
      sp-check --rule "user_action_required" \
        --min-actions 1 \
        --require-labels ["刷新页面","导出历史","等待自动恢复"]
    failure(): |
      echo "❌ 语义违规：错误状态缺少用户行动指引"
      exit 1

⚠️ 请求过于频繁，系统出现严重错误

红色背景 · 无恢复指引 · 用户恐慌性刷新

• AI 把 retryable 做成了 fatal 级别的视觉
• 用户看到"严重错误"，以为数据丢失
• 其实等 30 秒就好，但用户 panic 了

✓ 注入契约后 · 合规生成

• 机器先查 ERR-001.yaml → 匹配 retryable
