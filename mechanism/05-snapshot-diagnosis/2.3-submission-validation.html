失真的快照能入库吗？ Submission Validation

模板保证了结构完整，智能体保证了草稿可信，但提交前的最后一道防线是什么？
提交校验通过三层规则链，确保失真的快照被拦住不入库。

1

字段完整性校验

6 字段全部非空、类型正确、取值在枚举范围内

2

语义一致性校验

字段间逻辑自洽：component_type 与 visual.icon 匹配、context 与 deviation.type 匹配

3

字典引用合法性校验

所有语义令牌必须在语义字典中注册，未注册引用直接阻断

语义一致性校验
冲突：deviation.severity = "retryable" 但 visual.color = "red"
retryable 级别预期 visual 为 yellow，实际为 red
[入库阻断] snapshot-semantic-inconsistency
偏差描述与视觉特征不一致：severity 为 retryable 时，color 应为 yellow 而非 red
建议：修正 deviation.severity 为 "fatal" 或修正 visual.color 为 "yellow"

三层校验规则链

Rule 1 · 字段完整性
• 6 字段全部非空
• 字段类型匹配 schema
• 枚举值在允许范围内
• 字符串长度在限制内

Rule 2 · 语义一致性
• severity 与 color 匹配
• component_type 与 icon 匹配
• context 与 deviation.type 匹配
• actions 与 context 匹配

• icon_token 在字典注册
