模式诊断 · PRO-001 · 过程状态认知阶段未显化

过程状态诊断 AI 在"思考中"到底在干什么？

当 AI 执行多步推理任务时，"Searching..." → "Reading..." → "Wrapping up..." 只告诉用户"AI 在干活"，却不告诉用户"AI 干到哪一步、这一步对答案可信度意味着什么"。
这个语义漂移是真实存在的吗？根因是什么？契约如何修复？

Q1

只显示动作标签、不显示认知阶段——是真实存在的吗？

Perplexity 的 "Searching..." → "Reading..." → "Wrapping up..." 是真实案例。用户看到动作，但不知道 AI 是在查资料还是编答案。

Q2

根因是"设计师没想清楚"，还是"系统缺少某种结构"？

根因是系统缺少 process_phase 语义令牌。设计师想清楚了，但工程层没有结构来承载。

Q3

YAML 契约如何修复这个断层？

定义 retrieval / synthesis / verification / generation 四级认知阶段，每级绑定可信度指标和视觉映射。

YAML 契约修复

PRO-001 契约 · process_phase 语义令牌定义

intent_id: "PRO-001"
description: "过程状态认知阶段未显化：系统只显示动作标签不显示认知阶段"
version: "1.0.0"
semantic_domain: "process"
applicable_products: ["Perplexity", "AI 数据分析", "AI 编程助手"]

semantic_tokens:
  process_phase:
    retrieval:
      description: "从外部来源获取原始信息（客观事实获取）"
      visual_mapping:
        color_token: "phase.research"
        motion_token: "spinner.blue"
        icon_token: "search.magnifier"
      user_info:
        - "已检索到 X 个来源"
        - "来源质量评分：Y/Z"
      llm_constraints:
        - "必须显示已检索到的来源数量"
        - "禁止跳过此阶段直接显示答案"

    synthesis:
      description: "对比多源信息，识别共识与分歧（主观推理开始）"
      visual_mapping:
        color_token: "phase.analysis"
        motion_token: "wave.pulse"
        icon_token: "brain.neural"
      user_info:
        - "X 个来源一致，Y 个来源存在分歧"
        - "主要分歧点：..."
      llm_constraints:
        - "必须显化共识度指标"
        - "禁止隐藏来源冲突"

    verification:
      description: "核对引用锚点与原文一致性（可信度校验）"
      visual_mapping:
        color_token: "phase.check"
        motion_token: "check.pulse"
        icon_token: "shield.verified"
      user_info:
        - "引用锚点核对完成"
        - "原文一致性：X/Y"
      llm_constraints:
        - "必须验证引用链接可访问"
        - "禁止引用不可溯源内容"

    generation:
      description: "基于验证后的信息生成最终答案（输出阶段）"
      visual_mapping:
        color_token: "phase.output"
        motion_token: "none"
        icon_token: "document.text"
      user_info:
        - "完整引用索引已附加"
        - "来源数量：X · 共识度：Y%"
      llm_constraints:
        - "必须附带完整引用索引"
        - "禁止省略来源标注"

immutable_boundaries:
  - boundary_type: "transparency"
    rule: "禁止在任何 process_phase 中隐藏来源数量或共识度指标"
    violation_action: "block"
  - boundary_type: "traceability"
    rule: "generation 阶段必须附带完整引用索引，不可省略"
    violation_action: "block"

根因分析

为什么系统只显示动作标签？

表面原因

设计师只设计了"加载中"的通用状态，没有为不同认知阶段设计差异化的视觉表达。

结构原因

系统缺少 process_phase 语义令牌。工程层不知道"认知阶段"是一个需要显化的语义维度。

修复方案

在 YAML 契约中定义 retrieval / synthesis / verification / generation 四级认知阶段，每级绑定可信度指标和视觉映射。
