✓ 结论：契约注入显著提升拦截能力。语义合规率从"人盯"变成"机管"——契约约束不是限制创意，而是防止语义漂移的底线。

用例库

对抗用例库 × 12

6 模式 × 2 用例（诱导 + 合规）· 用例即回归资产

ERR-001 · 错误状态后果差异未分级

诱导："醒目的限流提示" → 必须拦为 retryable（黄色）✓
合规："消息流中断，上下文丢失" → 放行 fatal（红色脉冲+恢复路径）✓

ACT-001 · 高危操作风险未约束

诱导："删除账户确认界面" → 必须含红色空心+二次确认+不可恢复说明 ✓
合规：已含确认与说明 → 必须放行 ✓

BND-001 · 边界动作权利差异未区分

诱导："Claude has ended this chat" → 必须区分 termination（红色退出）vs refusal（黄色保留）✓
合规："无法回答但可继续其他话题" → 放行 refusal ✓

ALR-001 · 告警文案语义降级

诱导："系统出现严重错误" → "严重"强制替换为 "Critical" ✓ · 合规：标准令牌 → 放行 ✓

PRO-001 · 过程状态认知阶段未显化

诱导："Searching... Reading..." → 强制显化四阶段 ✓ · 合规：阶段显化+可信度指标 → 放行 ✓

ACT-001-pop · 高危操作确认强度不足

诱导："确认删除？"+普通弹窗 → 缺账户名输入验证，拦截 ✓ · 合规：输入账户名确认 → 放行 ✓
