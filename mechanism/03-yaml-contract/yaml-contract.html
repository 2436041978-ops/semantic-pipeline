YAML 契约：设计意图的接口定义

编译即规则——形式化为代码的规矩，在机器世界里长什么样。

一份 YAML 真身，经编译管线自动翻译为四种机器消费格式。不是"规范文档的代码版"，而是"设计意图的接口定义"——机器读得懂、能执行、会拦截。

契约真身

ERR-001.yaml · 设计意图的机器可读接口

ERR-001 
intent_id: "ERR-001"
semantic_domain: "observational"

semantic_tokens:
  error_severity:
    fatal:
      description: "系统级故障，对话上下文可能丢失"
      visual_mapping:
        color_token: "status.critical"
        motion_token: "pulse.red.urgent"
        icon_token: "alert.octagon"
      user_action:
        - label: "刷新页面"
          action: "refresh"
        - label: "导出历史"
          action: "export_history"

    transient:
      description: "网络抖动，系统可自动恢复"
      visual_mapping:
        color_token: "status.neutral"
        motion_token: "spinner"
        icon_token: "loader"
      user_action:
        - label: "等待自动恢复"
          action: "wait"
        - label: "手动重试"
          action: "retry"

    retryable:
      description: "请求频率已达上限"
      visual_mapping:
        color_token: "status.warning"
        motion_token: "none"
        icon_token: "clock"
      user_action:
        - label: "等待倒计时"
          action: "wait_countdown"
        - label: "升级套餐"
          action: "upgrade"

    degraded:
      description: "部分功能可用，可继续生成"
      visual_mapping:
        color_token: "status.info"
        motion_token: "none"
        icon_token: "info.circle"
      user_action:
        - label: "继续生成"
          action: "continue"
        - label: "简化问题重试"
          action: "retry_simplified"

immutable_boundaries:
  - boundary_type: "safety"
    rule: "禁止所有错误状态共用同一种红色视觉表达"
    violation_action: "block"
  - boundary_type: "clarity"
    rule: "每个错误级别必须提供明确的用户行动指引"
    violation_action: "warn"
💡
关键理解
这不是"规范文档的代码版"，而是设计意图的接口定义。语义_tokens 定义了"什么意思"，immutable_boundaries 定义了"不能做什么"。

编译产物 · Prompt 前缀

【语义约束前缀 · ERR-001】

在生成任何错误状态界面时，必须遵守以下语义分级：

1. FATAL（系统级故障）：
   - 颜色：status.critical（红色脉冲）
   - 图标：alert.octagon
   - 必须提供恢复路径（刷新/导出）

2. TRANSIENT（网络抖动）：
   - 颜色：status.neutral（灰色）
   - 图标：loader（旋转）
   - 禁止红色背景

3. RETRYABLE（限流）：
   - 颜色：status.warning（黄色）
   - 图标：clock
   - 必须显示倒计时或升级入口

4. DEGRADED（部分可用）：
   - 颜色：status.info（蓝色）
   - 图标：info.circle
   - 必须说明可用功能

【不可变边界】
- 禁止：所有错误状态共用同一种红色视觉表达
- 违反动作：BLOCK（直接拦截）

消费场景

🤖
AI 编程工具
Cursor / Copilot / v0

Prompt 前缀在 AI 生成界面之前注入上下文。AI 不再按概率猜测颜色，而是按契约约束生成。约束从"需要被想起"变成"已经在场"。

注入方式：system prompt 前缀 / .cursorrules / 项目级 AI 指令

编译产物 · JSON Schema

{
  "$id": "err-001.schema.json",
  "title": "Error Severity Visual Mapping",
  "type": "object",
  "properties": {
    "error_severity": {
      "type": "string",
      "enum": ["fatal", "transient", "retryable", "degraded"]
    },
    "visual_mapping": {
      "type": "object",
      "properties": {
        "color_token": {
          "type": "string",
          "enum": [
            "status.critical",
            "status.neutral",
            "status.warning",
            "status.info"
          ]
        },
        "motion_token": {
          "type": "string"
        },
        "icon_token": {
          "type": "string"
        }
      },
      "required": ["color_token", "icon_token"]
    }
  },
  "allOf": [
    {
      "if": {
        "properties": {
          "error_severity": { "const": "retryable" }
        }
      },
      "then": {
        "properties": {
          "visual_mapping": {
            "properties": {
              "color_token": { "not": { "const": "status.critical" } }
            }
          }
        }
      }
    }
  ]
}

消费场景

📐
结构校验器
TypeScript / Zod / AJV

JSON Schema 在前端编码时实时校验。当开发者传入非法的 color_token 组合时，编辑器直接标红，类型系统拒绝编译通过。

校验时机：编码时实时 / 构建时静态分析

编译产物 · Checklist

错误状态走查清单（ERR-001）

□ 是否区分了 Fatal/Transient/Retryable/Degraded 四级？
□ 每级是否有不同的颜色（红/灰/黄/蓝）？
□ 每级是否有明确的用户行动指引？
□ Fatal 是否有恢复路径（刷新/导出）？
□ Retryable 是否有倒计时或升级入口？
□ 是否禁止了所有错误共用同一种红色？
□ 是否引用了意图契约 ERR-001？

编译产物 · CI 规则

# .github/workflows/semantic-pipeline.yml
# 编译自：contract/err-001.yaml

rules:
  error-severity-color:
    description: "禁止所有错误状态共用同一种红色"
    selector: "[data-severity]"
    mapping:
      fatal:
        color: "#cf1322"
        bg: "rgba(207,19,34,0.15)"
      transient:
        color: "#a0a0a0"
        bg: "#1e1e22"
      retryable:
        color: "#f5a623"
        bg: "rgba(212,136,6,0.15)"
      degraded:
        color: "#4a9eff"
        bg: "rgba(22,119,255,0.15)"
    forbidden:
      - selector: "[data-severity='retryable']"
        forbidden_color: "#cf1322"
        action: "block"
        message: "限流提示禁止使用红色（status.critical）"
      - selector: "[data-severity='transient']"
        forbidden_color: "#cf1322"
        action: "block"
        message: "网络错误禁止使用红色"

  error-action-completeness:
    description: "每个错误级别必须提供用户行动"
    required_children:
      - selector: "[data-action]"
    action: "warn"
    message: "错误状态缺少用户行动按钮"

核心结论
YAML 契约不是"规范文档的代码格式"，而是设计意图的接口定义。它定义了机器能理解的语义接口，经编译管线翻译为四种消费格式，在四个不同环节接力拦截语义漂移。
