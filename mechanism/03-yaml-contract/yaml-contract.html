机器形态 1：Prompt 前缀（给 AI 编程工具）— 自动注入 Claude Code / Cursor 上下文

# 由编译管线从 ERR-001.yaml 自动生成
# 版本: v1.1.0 | 生成时间: 2026-07-12T13:40:00Z

[SEMANTIC_CONSTRAINTS_START]

你在生成错误状态界面时，必须遵守以下语义分级规则：

1. FATAL（系统级故障）：
   - 必须使用红色脉冲 + 八边形警告图标
   - 必须提供恢复路径（刷新页面 / 导出历史）
   - 禁止仅显示"出错了"等模糊文案

2. TRANSIENT（网络抖动）：
   - 必须使用灰色加载 + 旋转图标
   - 禁止红色背景
   - 必须说明"系统正在自动恢复"

3. RETRYABLE（限流）：
   - 必须使用黄色提示 + 时钟图标
   - 必须显示倒计时
   - 必须提供升级入口

4. DEGRADED（部分可用）：
   - 必须使用蓝色提示 + 信息图标
   - 必须说明哪些功能仍然可用
   - 必须提供"继续生成"选项

不可变边界（强制执行）：
- 禁止所有错误状态共用同一种红色视觉表达
- 每个错误级别必须提供明确的用户行动指引

[SEMANTIC_CONSTRAINTS_END]

机器形态 4：CI 规则（给自动化流水线）— GitHub Actions / ESLint 自动拦截

# .github/workflows/semantic-check.yml
# 由编译管线从 ERR-001.yaml 自动生成

name: Semantic Contract Check
on: [pull_request]

jobs:
  semantic-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Load Semantic Contract
        run: |
          pip install semantic-pipeline
          sp-load intent/err-001.yaml

      - name: Check Error Severity Colors
        run: |
          sp-check \
            --rule "error_severity_color" \
            --forbid "status.critical" for "retryable" \
            --forbid "status.critical" for "transient" \
            --forbid "status.critical" for "degraded"
        failure(): |
          echo "❌ 语义违规：错误状态颜色映射不符合契约"
          echo "修正建议："
          echo "  - retryable → status.warning（黄色）"
          echo "  - transient → status.neutral（灰色）"
          echo "  - degraded → status.info（蓝色）"
          exit 1

      - name: Check User Actions
        run: |
          sp-check \
            --rule "user_action_required" \
            --min-actions 1 \
            --require-labels ["刷新页面", "导出历史", "等待自动恢复"]
        failure(): |
          echo "❌ 语义违规：错误状态缺少用户行动指引"
          exit 1

机器拦截现场

当 AI 试图生成违规内容时，机器如何拦截？

❌ 未注入契约 违规通过
⚠️ 请求过于频繁，系统出现严重错误
红色背景 · 无恢复指引 · 用户恐慌性刷新
• AI 把 retryable 做成了 fatal 级别的视觉
• 用户看到"严重错误"，以为数据丢失
• 其实等 30 秒就好，但用户 panic 了
✓ 注入契约后 合规生成
⏱️ 请求过于频繁，请在 42 秒后重试
黄色提示 · 时钟图标 · 倒计时 + 升级入口
• 机器先查 ERR-001.yaml → 匹配 retryable
• 拦截：禁止用"严重"描述限流，禁止红色
• 返回修正建议 → AI 重新生成合规内容
