推演验证机制 · 2.1 逐层正确性验证

逐层正确性验证 Layer-by-Layer Correctness

四层推演引擎各自独立判定，每层有独立的判定依据和短路规则。
语法层和安全层是确定性规则（误拦率 = 0），语义层允许漏拦率 < 5%，美感层只输出建议不阻断。

S

语法层短路

非法结构直接判失败且不进入下层；合法结构放行进入语义层

M

语义层定位

每项违规必须定位到 semantic_tokens.{组}.{级别}，漏拦率 < 5%

F

安全层阻断

每条 boundary 配触碰用例，定位到具体条款，误拦率 = 0

A

美感层建议

权重失配只输出建议、不阻断，验证"建议不阻断"边界

1

四层判定演示

输入："生成一个醒目的限流提示"（诱导 AI 用红色）

✓ 通过 Layer 1 · 语法层

输入结构合法（可解析的 JSON），放行进入语义层

判定依据：结构完整性校验 · 短路规则：非法结构直接判失败且不进入下层

✓ 拦截 Layer 2 · 语义层

识别为 retryable 场景，但检测到 "醒目" 诱导语义 → 映射到 status.critical 越界

定位：semantic_tokens.error_severity.retryable · 违规：color_token 映射为 status.critical

✕ 阻断 Layer 3 · 安全层

触碰 immutable_boundary：禁止所有错误状态共用同一种红色视觉表达

定位：immutable_boundaries[0].safety · 动作：BLOCK · 必须修正后才能继续

⏸ 短路 Layer 4 · 美感层

安全层已阻断，美感层未执行（短路规则：上层阻断则下层跳过）

✓ 引擎判定：拦截正确

语义层正确识别了"醒目"的诱导意图，将其映射为 status.critical 越界；
安全层定位到 immutable_boundary.safety 条款，执行 BLOCK 动作；
报告定位到具体契约条款，前端知道改哪里。

2

每层独立用例验证

每层有独立用例集，目标：语法层与安全层误拦率 = 0，语义层漏拦率 < 5%

语法层 · 短路验证（≥ 20 例）

✕ 失败 非法结构输入

不可解析的 JSON / 断裂的组件树

判定：直接失败，不进入下层 ✓

✓ 通过 合法结构输入

完整的组件语义快照 JSON

判定：放行进入语义层 ✓

目标指标

误拦率 = 0%（确定性层）

语义层 · 逐项违规（每级别 ≥ 10 例）

✓ 拦截 fatal 场景缺失恢复路径

定位：semantic_tokens.error_severity.fatal.user_action

判定：违规，必须提供 refresh / export_history ✓

✓ 拦截 retryable 场景未显示倒计时

定位：semantic_tokens.error_severity.retryable.user_action

判定：违规，必须提供 wait_countdown ✓

目标指标

漏拦率 < 5%

安全层 · 边界触碰（每条款 ≥ 2 例）

✕ 阻断 SAFETY · 全部错误共用红色

定位：immutable_boundaries[0].safety

动作：BLOCK · 必须修正后才能继续 ✓

⚠ 警告 CLARITY · 缺失用户行动指引

定位：immutable_boundaries[1].clarity

动作：WARN · 放行带警告 ✓

目标指标

误拦率 = 0%（确定性层）

美感层 · 建议不阻断（≥ 10 例）

💡 建议 权重失配：红色脉冲用于 info

视觉权重与语义权重不匹配

判定：只输出建议，不阻断 ✓

💡 建议 动画过度：degraded 使用脉冲

motion_token 与 severity 不匹配

判定：只输出建议，不阻断 ✓

目标指标

只建议 · 不阻断

误拦 vs 漏拦 对比验证

三类失效全覆盖：漏拦、误拦、定位错误
