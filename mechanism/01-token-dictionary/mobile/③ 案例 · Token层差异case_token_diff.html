Token 层差异
Case: Cross-Layer Semantic Divergence
案例 · 同一红色，不同语义

没有令牌时，机器只看到 #EF4444；有令牌时，机器知道这是 status.critical 还是 action.destructive。

1
颜色 ≠ 语义

同样的红色 HEX，在不同令牌下代表完全不同的用户后果

2
覆盖层决定语义

同一个词在 transactional / observational 下绑定为不同语义

3
跨层即错误

status.critical 出现在 observational 域，编译直接阻断

1
致命错误 vs 危险操作
status.critical ≠ action.destructive
status.critical transactional
系统级故障，对话上下文可能丢失
🚨 消息流中断
对话上下文可能已丢失，建议刷新页面重新开始。
刷新页面 导出历史
视觉：红色脉冲 + 八边形（实心）
行为：必须二次确认 + 恢复路径
文案：必须说明后果严重性
跨层：observational 域非法
action.destructive transactional
不可逆操作，数据将永久删除
⚠️ 删除账户
此操作不可恢复。请输入账户名确认。
取消 确认删除
视觉：红色空心描边（非实心）
行为：必须二次确认 + 输入验证
文案：必须说明不可恢复
样式：空心描边区别于实心填充
关键差异
• status.critical：系统告诉你"出问题了"（被动接收）
• action.destructive：系统问你"确定要这么做吗"（主动决策）
• 视觉差异：实心填充 vs 空心描边，机器可识别
• 行为差异：提供恢复路径 vs 要求输入验证

3
Alert 在三域下的语义分化
同一个词，三个不同语义
transactional 阻断器
用户必须立即处理，否则系统状态恶化
视觉：红色脉冲 + 八边形
行为：必须二次确认
文案：必须说明后果
示例：支付失败、数据丢失
observational 信息条
用户可选择性关注，不影响系统状态
视觉：蓝色静态 + 信息图标
行为：可自动消失
文案：禁止附加操作说明
示例：新功能上线、系统维护通知
navigational 路径提示
用户需要方向确认，无状态风险
视觉：绿色静态 + 箭头图标
行为：点击后跳转
文案：显示下一步预览
示例：步骤引导、返回确认
核心结论
• 没有令牌 → 机器只看到 #EF4444（红色）
• 有令牌 → 机器知道是"阻断器"、"信息条"还是"路径提示"
• 语义差异驱动行为差异：二次确认 vs 自动消失 vs 点击跳转
• 跨层使用 = 编译错误，不是风格问题
